# Known limitations and remaining release verification

- Engine 1.1.0 and earlier failed the independent Milestone 3 gate: future daily volume, nonchronological protection, pre-cost risk limits, opening take-profit ordering and zero-equity metrics had confirmed defects. Engine 1.2.0 corrects these. Previously completed results remain immutable and are not retroactively certified; rerun them with the corrected engine before relying on them. See `milestone-3-review.md`.

- Docker Desktop/WSL 2 Linux build/start, migrations, Nginx/API/PostgreSQL/worker connectivity, and stored-input/result persistence across service restart and container recreation are now verified on Windows. The current backend suite passes 63 cases including PostgreSQL in a disposable Linux container. The diagnostic uses explicitly synthetic data and an isolated volume/loopback port 18080. Standalone Ubuntu and external-database configurations, unattended startup after a Windows reboot, and backup/recovery have not been demonstrated. See `deployment-verification.md` for evidence and lifecycle commands.
- The backend test count includes unit, API and database integration cases; no coverage percentage is claimed. Provider HTTP is mocked or blocked, even when dummy credentials are present. This isolates automated tests from real keys but does not certify live provider responses or source-data completeness. The missing-key LLM test's former environment inheritance was corrected before real credentials were supplied. See `testing.md`.
- Alpaca and OpenAI keys have now been supplied. Paper-account authentication and import of 1,259 real SPY SIP bars for 2018–2022 passed; the imported revision has no missing sessions but deliberately remains unreviewed, with no FX/actions. Scheduling is blocked and no real backtests/returns were created. The earlier completed demonstration/results remain explicitly synthetic.
- Live OpenAI authoring reached the provider but returned HTTP 429 `credit_balance_exhausted`/`insufficient_quota`. Generation, modification and output quality remain unverified until usable credit/billing is restored. GPT-6 Luna is the cost-focused recommendation; neither model has an app-specific head-to-head quality/latency measurement here. The client does not explicitly set reasoning effort, so Luna's medium default differs from Mini's none default.
- Alpaca supports explicitly selected SIP or IEX. The UI defaults to SIP; legacy API calls retain IEX. IEX is not consolidated volume. Historical SIP access succeeded on the supplied account; no subscription was changed. Either feed's bars may be revised, and 20:15 New York time availability is an assumption. Strict vintage research needs source-provided availability vintages. CSV imports depend on truthful source metadata and complete corporate actions. Missing splits cannot be reliably inferred from prices alone.
- ALFRED DEXSIUS is the free FX candidate, not an integrated or accepted dataset. Daily observation dates precede the weekly H.10 publication; using same-day availability would leak future information. Actual vintage coverage/publication evidence remains unverified. Weekly lag can exceed the profile's default seven-day age, requiring an explicitly reviewed 14-day profile setting or a different qualified source. Reference rates do not model executable conversion quotes. ECB latest-history cross-rates are not automatically vintage-safe either.
- SPY 2018–2022 issuer distributions, payment dates, declaration availability and split coverage have not been reconciled. Both import methods retain dividend-completeness attestations, but checked boxes do not establish source correctness. Missing pre-open declaration evidence blocks certification. No real-data returns, independent selected-fill reconciliation or repeat-run comparisons have been demonstrated in this phase. See `deployment-verification.md` for specific required inputs and safe deployment procedures.
- Real raw datasets cannot be backtested until the source's corporate-action coverage has been explicitly reviewed and all effective splits supplied. This is a source-owner attestation, not automatic independent verification. The import forms expose it and new revisions preserve it in their content hash. Unfinished API daily bars are rejected.
- The calendar is regular-session XNYS (also used for US Nasdaq-listed instruments), 1990–2035. Exact per-venue halts/delistings and historical universe membership are not modeled. Missing in-period sessions reject the run. Manually chosen current symbols can cause survivorship bias.
- Full fills, fixed daily slippage/spread, no market-impact model, and whole-position exits. No pyramiding, partial fills, tax/withholding, margin, shorts, cash interest, cash-in-lieu or dividend reinvestment. Protective fill timestamps/FX use the disclosed conservative daily-bar convention. Minimum-notional rules can leave unsellable dust.
- Computation is single-process per worker and bounded by dataset/queue limits. Large daily universes/results remain memory resident during simulation; cancellation checks occur per session, with half-second database polling. A stale worker fails visibly rather than automatically retrying. SQLite is for one local worker, PostgreSQL for deployment/concurrency.
- Data imports are bounded synchronous HTTP operations; backtests always run in the separate worker. Provider calls may take up to the reverse proxy timeout; use smaller import ranges when needed.
- The MVP has no login. Keep loopback bindings or put it behind an authenticated trusted access layer. API keys stay on the server. Do not publicly redistribute source market data.
- The version comparison UI shows definitions side by side, with exact numeric fields in JSON. Automated hyperparameter optimization, ML workflows, intraday data, ensembles and paper/live trading are deferred.
- Backend dependencies currently emit third-party TestClient/Pandas deprecation notices. Tests pass; no runtime monkeypatch or warning suppression hides them.
